# 賽博雷音：規格書與邊界條件

> 版本 0.1 · 2026-11-04 · 由 GATEWAY-BCI 原始文件（V1.0）經物理檢討後改寫

## 1. 目的

**個人體驗。** 用 App 合成「像某種念誦口型發出的聲音」，經骨傳導耳機送進頭骨，透過調整頻率與頻譜，試著讓顱內的共振部位變化、移動，達到類似道家雷音法、密宗梵音的按摩感；同時保留 Hemi-Sync（雙耳節拍）能發生的條件。

不是科學實驗：不做盲測統計、不做嚴格紀錄，但架構上留接口（見 §7）。

## 3. 物理邊界

### 3.1 原文件中做不到的部分

| 原設計 | 問題 |
|---|---|
| 橫條 II：ITD ±500 µs 讓嗡鳴「定錨」在左腦／右腦／松果體 | 204 Hz 下 500 µs 只是 ±36.7° 相位；雙耳節拍的左右相位差本來就每 250 ms 轉一整圈，ITD 只讓節拍起點位移約 25 ms，定不住位置 |
| 橫條 III：反相混入以消除串音 | 只調比例不夠，還要對齊延遲；而且「消除串音」和按摩目的相反 |
| 純正弦波＋時間差移動顱內位置 | 200 Hz 純音下頭骨近似整塊一起振動，靠時間差無法在骨頭內形成局部聚焦 |
| 嚴禁 MP3/AAC | 走藍牙就一定經過 SBC／AAC 有損編碼；只有 OpenSwim Pro 內建播放能繞過 |

### 3.2 有效機制：改頻譜，不改時間差

念誦時改口型，改的是**頻譜形狀**（哪些泛音被放大，即共振峰）。頭內有口腔、咽喉、鼻腔、鼻竇等空腔，各有不同共振頻率；被放大的頻段不同，被推動的部位就不同。這是使用者實踐中「共振部位會變化、移動」的聲學解釋，也是本專案的核心機制。

### 3.3 骨傳導的特性

- 左右振子的聲音會穿過頭骨漏到另一側耳蝸（低頻穿顱衰減約 0–10 dB）。所以 OpenSwim Pro 上的 4 Hz 感受，會混入「物理拍頻」，不只是大腦合成的雙耳節拍。Bose 上則接近純雙耳節拍。
- 皮膚與骨膜的震動感受在約 200–250 Hz 最敏感，原文件選 200 Hz 載波對按摩感是好選擇。
- 振子固定在耳前，**能用訊號控制的位置只有左右一個方向**；前後上下只能靠頻譜（§3.2）或實際挪動配戴位置。
- 聲源在體外（耳前骨面），和念誦時聲源在體內不同；胸腔共振大概推不動。能不能重現念誦的部位感，**無法事先保證，要親自比對**。

### 3.4 證據邊界

CIA 的 Gateway 文件（1983）是內部分析，不是驗證結果；雙耳節拍帶動腦波的研究結論不一致。本工具能宣稱的只有主觀感受。

## 4. 控制設計（第一版）

**兩個獨立維度**（使用者 2026-11-04 釐清）：

1. **4 Hz 在腦中繞**：左右分開的雙耳節拍，全程保持。
2. **按摩感 = 音色本身的共振**：像音叉，找到與顱內某個空腔或整顆頭共振的頻率／頻譜，讓該部位被「點亮」。**不是**靠左右互混產生的物理拍頻。

**4 Hz 與音色互不干擾的做法：整組平移。** 右耳的每一個頻率成分都比左耳剛好高 4 Hz（不是左右各用不同基頻，否則第 n 泛音的差會變成 4n Hz）。用加法合成（逐一產生每個泛音）實作。

| 控制 | 範圍（暫定） | 作用 |
|---|---|---|
| 音色模式 | 單音（音叉）／口型 | 單音 = 純正弦；口型 = 多泛音加共振峰 |
| 共振頻率 | 約 80–1000 Hz | 單音模式的音高；口型模式的基頻。主要的「找共振」旋鈕 |
| 口型觸控板（XY） | 上下 = 開口大小（第一共振峰 約 300–900 Hz）；左右 = 舌位前後（第二共振峰 約 700–2500 Hz） | 手指連續拖動 = 連續改口型，對應使用者雷音訓練中「改口型微操共振點位、可連續細調」的做法。u／o／a／e／i 只是平面上的地標 |
| 鼻音量 | 0–100% | m／ng 類，往鼻腔走的成分 |
| 圓唇 | 0–100% | 嘴唇收圓，所有共振峰往下拉 |
| 精細模式 | 開／關 | 手指大幅移動、參數小幅變化，用於細部微調 |
| 差頻 | 0–8 Hz，預設 4 Hz | Hemi-Sync；所有成分整組平移；0 = 無節拍 |
| 左右強度 | 左 100% ～ 右 100% | 原橫條 I |
| 音量 | 有上限 | 安全 |
| 進階（收合） | 混合度、ITD、串音延遲 | 混合度兩端體感：**「腦中繞」↔「一鬆一緊」**（通話時藍牙單聲道即為右端）；預設 0，不是按摩的主機制 |

**找共振的兩種方式**（都可隨時按一下記錄「目前參數＋共振部位」，累積成個人的顱內共振地圖）：

- **主要：手動微操**。在口型觸控板上拖動、調共振頻率，像雷音訓練一樣主動找。
- **輔助：自動掃頻**。頻率或口型由程式慢速掃過，不知道從哪裡開始時先粗略掃一遍。

**物理註記**：雙耳節拍在載波約 1 kHz 以下最明顯，更高的成分主要貢獻音色與共振，不太貢獻 4 Hz。骨傳導會漏音，OpenSwim Pro 上的 4 Hz 一定帶一點「一鬆一緊」。

所有參數集中在單一設定物件，供匯出、預設組、掃頻紀錄、未來紀錄共用。

## 5. 架構

- 純前端靜態網頁，不需伺服器。
- 音訊引擎：Web Audio API。精確合成用 AudioWorklet（需要 HTTPS 或 localhost）。
- PWA：manifest＋安裝到主畫面；Media Session 提供鎖定畫面控制。
- 匯出：同一套合成程式離線渲染成 WAV（用 OfflineAudioContext），供背景播放後備方案。

## 6. 待查證（開發前）

1. **S26 Ultra 關螢幕後能否持續播放網頁音訊**：用 `spike/bg-audio/` 測三種播放方式。三星可能需要把 Chrome 設成「永不休眠」。
2. **OpenSwim Pro MP3 模式支援的格式**：WAV／FLAC 是否可用。
3. Bose 主動降噪對 200 Hz 左右的影響：開關降噪各聽一次。

## 7. 留接口、暫不實作

- 紀錄：把設定物件加時間戳存下並匯出。
- 盲測：程式代替使用者隨機切換「差頻 0／4 Hz」，使用者猜，最後對答案。
- 念誦校準：錄使用者自己念某個音，分析基頻與共振峰，讓合成器照這組數值重現。
- 串音消除（振幅＋延遲兩參數），以及 ITD。

## 7.5 已觀察到的問題

- **2026-11-04，S26 Ultra＋OpenSwim Pro，播放方式 A（Web Audio 直接輸出）**：播放中來了 LINE 電話，接起後**通話完全沒有聲音**，要關掉所有程式後重撥才正常。**原因未確定**，兩個假設：(1) 當時 OpenSwim Pro 被電腦連走，通話聲音送不到耳機；(2) Web Audio 直接輸出沒有參與 Android 的「音訊焦點」。可用「播放中開 YouTube 搶焦點」分辨，不必等來電。
  - 要求：正式版**來電時一定要讓出聲音**。優先採用經由播放器元素的方式（B 或 C），由瀏覽器處理音訊焦點；另在通知列放「停止」按鈕。
  - 待驗證：C、D 在來電時是否會自動暫停、通話是否正常、掛斷後能否恢復。
- **同日，播放方式 B（Web Audio 轉接播放器元素）**：S26 Ultra 上有雜音和斷音，音質不可用，淘汰。
  - 改測 **D：A 的直接輸出＋一個約 -90 dB 的循環播放器元素當「焦點代理」**；代理被系統暫停（來電、通知列）時，程式跟著暫停音訊引擎，恢復時跟著恢復。
- 注意：OpenSwim Pro 同時配對電腦與手機，測試時要確認它連在手機上。

## 7.6 已驗證

- **方式 A 背景播放（2026-11-04，S26 Ultra，Chrome 分頁，未加到主畫面）**：關螢幕 1213 秒（約 20 分鐘），音訊前進 1213 秒，全程沒斷；背景計時器最長停頓 1 秒，代表 Chrome 沒有節流這個頁面。**主方案可行。**
- **方式 A 的音訊焦點：不合格**。A 播放中打開 YouTube，兩邊聲音原樣同時出來，A 不會讓出。正式版不能只用 A。
- **方式 A 遇到通話**：A 播放中開 Discord 語音通話，A 的聲音會停。通話時系統切換到通話音訊模式，媒體聲音被系統擋下，跟 A 有沒有讓出焦點無關。由此推論 LINE 來電無聲，較可能是當時耳機被電腦連走。
- **方式 A 通話結束後**：不會自己恢復，要切回 Chrome 那個分頁聲音才回來。正式版需要不開頁面就能恢復的方法，例如通知列／鎖定畫面的媒體卡片，這要靠 D 的焦點代理提供。
- **方式 D 的音訊焦點：合格**。D 播放中開 YouTube，D 會停。關掉 YouTube 不會自己恢復（Android 不保證歸還焦點，屬預期）。測試頁原本沒有「繼續」按鈕，已補上。
- 尚待：通知列有沒有媒體卡片、從卡片或「繼續播放」鈕能不能恢復。
- **方式 D 背景播放（v1 代理 -90 dB）：不合格**，關螢幕約 3 分鐘就停。推測 Chrome 把低於約 -72 dBFS 的播放器視為靜音，在背景將其暫停，連帶觸發程式停止聲音。已改為 -60 dBFS 的同頻代理（v2），待測。
- **通話中的音質（A、D 皆同）**：聲音變成「忽大忽小」。原因是藍牙切到通話模式（單聲道、電話音質），左 200 Hz／右 204 Hz 被混成同一聲道，形成 4 Hz 物理拍頻，等於「混合度 100%」，Hemi-Sync 消失。可作為混合度橫條的體感參考點。
  - 正式版待辦：通話中自動暫停。網頁無法直接偵測通話，候選訊號是 `navigator.mediaDevices` 的 `devicechange` 事件（藍牙切換模式時可能觸發），需實測。

## 8. 安全

- 程式內設音量上限；開始前先把系統音量調低。
- 單次時長上限（暫定 30 分鐘，可調）。
- 頭暈、耳鳴、頭痛就停。
- 不在開車、游泳或需要專注的場合使用。
